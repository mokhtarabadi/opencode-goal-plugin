# Decisions

## ADR-001 2026-10-16 File state owns truth

Context: compaction wipes memory. Decision: .opencode/goal-state.json is source of truth with atomic tmp plus rename writes and lease fields. Consequence: survives compaction, enables single-flight claim.
Superseded in part by ADR-010: the file remains the source of truth, but the path is now per session with the legacy file kept as a read fallback.

## ADR-002 2026-10-16 Claim-lock file serializes parallel claimants

Context: parallel idle turns shared one tmp name and raced load-modify-write. Decision: wx-flag lock file with stale reclaim plus unique tmp names per call. Consequence: exactly one winner proven by test, crashed runs cannot hold the lock past TTL.

## ADR-003 2026-10-16 Idle single-flight plus cooldown defaults

Context: idle ticks can re-fire while a turn runs. Decision: in-memory idleInFlight plus file lease plus 20s cooldown plus 30 turns plus 2h wall budget plus STOP_GOAL file. Consequence: one send per tick, human messages yield, runaways stop.

## ADR-004 2026-10-16 Compaction restore plus evidence-gated completion

Context: compaction wipes memory and self-report completes too easily. Decision: snapshot plus restore with restoreCount audit and cooldown clamp, evidence sidecar with file plus test proof, local verifier first with optional subagent second. Consequence: goals resume without double send, completion needs proof.

## ADR-005 2026-10-16 Host-native V2 export shape

Context: host loader rejected our plain-object default export as missing id. Decision: default export is Plugin.define with id opencode-goal-plugin plus setup wiring command, idle subscribe, and session hooks, ESM-only dist, @opencode/plugin dependency. Consequence: entry passes host schema on web, CLI, and TUI.

## ADR-006 2026-10-16 Best-plugin hardening without contract break

Context: clones showed crash truncation, double-fire, false complete, global throttle unfairness. Decision: fsync plus chmod plus quarantine, token single-flight plus fail-closed reclaim, evidence-gated helper plus wrapupSent plus nudge, per-session cooldown plus AbortSet, JSON Schema plus traversal guard, file-state stays truth. Consequence: 83 tests green with 7 new regressions, no V2 contract change.

## ADR-007 2026-10-16 Crash and error recovery for an active goal

Context: idle-only trigger stalled an active goal forever when the host emitted no session.idle after a server error or crash, and a failed send was swallowed as a fake success (catch to null then turn-unlabeled). Clone survey: only prevalentWare had a watchdog; heimoshuiyu plus willytop8 plus prevalentWare listened to session.error; goal-loop plus willytop8 paused recovered goals. Decision: subscribe session.error plus execution.failed plus execution.interrupted and classify user-abort versus provider-error; park on abort and park-require-resume; record pendingAttempt plus lastHeartbeatMs plus failureCount plus recoveryEpoch in file state; a 90s watchdog wakes before the 120s lease TTL and every wake re-enters the same lease plus token guard; session start rearms without an immediate send; a failed send stays retryable and never advances the turn; one wrap-up send then stop. Consequence: 102 tests green, an active goal survives a provider error, a failed send, and a restart, and the V2 contract (Plugin.define id plus setup, event.subscribe plus AbortController cleanup) is unchanged.
Rollback: revert this slice; the pure loop plus file state keep prior idle-only behavior.

## ADR-008 2026-10-17 Agent-callable goal tools beside the slash lane

Context: the model could only be driven by user slash commands or the idle loop; smart-compact showed an agent tool lane (compact_context) reusing command helpers. Decision: register goal_set, goal_block, goal_complete, goal_resume via ctx.tool.transform in new src/tools.ts, each execute calling the pure goal.js helpers directly with validated data (never rebuilding slash strings, so reserved-word titles cannot misroute), claiming the file lease under owner tool:<sessionID> before mutating, and returning handleGoalCommand-identical messages (parity-tested). Consequence: model-driven and user-driven paths share validation, evidence gate, Clock, and atomic save with zero drift, and parallel tool calls serialize instead of clobbering.
Rollback: remove the registerGoalTools call; file state untouched.

## ADR-009 2026-10-17 Sole evidence writer closes the completion loop

Context: goal_complete could never succeed because no code path ever wrote criteria into the evidence sidecar (both lanes only read it). Decision: add goal_evidence as the fifth agent tool and sole evidence writer plus a /goal evidence slash mirror delegating to the same recordEvidence handler; id, claim, files, tests all required with shape-only validation at write (existence plus passing stay verifier-side); duplicate ids rejected; writes only on active goals under the state-file lease. Consequence: set to evidence to complete passes with real proof while empty or fabricated evidence still fails, and the verifier plus evidence modules are untouched.
Rollback: remove the tool def plus the slash branch; the sidecar file is per-project runtime state, no migration involved.

## ADR-010 2026-10-21 Goal state is per session, legacy file is a read fallback

Context: one shared `.opencode/goal-state.json` meant a goal set in session A was visible to session B in the same project. The idle loop would continue A's objective inside B, `goal status` in B reported A's goal, the context hook injected A's objective into every model request in the project, and a `clear` in B silently killed A's goal. Multiple sessions per checkout is normal, not an edge case. Decision: state and evidence live at `.opencode/goals/<sanitized-session-id>.json` and `.evidence.json`, where a session id is sanitized to `[A-Za-z0-9_-]{1,64}` or replaced by a stable `sid-<fnv1a>` hash. `resolveStatePath` plus `resolveEvidencePath` gained an optional session id; callers without one keep the legacy path, so old invocations and tests stay valid. Scoped reads fall back to the legacy file once, and the next write lands on the scoped path (migrate-on-write, never rewriting legacy). Corrupt scoped state fails closed instead of falling back. Slash, tools, idle, failure, startup rearm, compaction, and context lanes all thread the real session id; lane markers `unknown` and `slash` deliberately map to legacy. Consequence: sessions in one project are isolated, old single-file users keep working and migrate on their first write, and the legacy path stays gitignored runtime state. Rollback: revert the path helpers plus the `sessionId` threading; the legacy file alone restores prior behavior.

## ADR-011 2026-10-22 Completion observes test results instead of trusting them

Context: `verifyLocal` accepted the `exitCode` recorded in the evidence sidecar, and that value is written by the agent through `goal_evidence`. The gate rejected empty proof but not false proof: an agent could record `npm test` with `exitCode: 0` without running anything. Decision: add `src/proof.ts` with `runProofCommand`, which executes a recorded command through the platform shell (`/bin/sh` on POSIX, the configured command processor on Windows), started in the project directory after an absolute-path check, with a 300s per-command timeout, a 1 MiB output cap, and a sha256 digest of the captured output for audit. The working directory is a starting point, not a sandbox: absolute paths and `cd` still reach the rest of the machine, and the runner must never receive a command from an untrusted party. `verifyLocal` gains an optional `runTests` mode that executes every non-empty recorded command for a criterion and requires each to exit 0, reporting `test-failed`, `test-timeout`, `test-not-run`, `test-cap`, or `test-budget` distinctly; running only one command would let a trivial pass mask a failing suite. `tryCompleteWithEvidence` enables the mode by default, so both complete lanes observe real results; direct `verifyLocal` callers keep the declare-only behavior. A 20-command cap plus a shared 600s pass deadline bound completion cost, and the slash lane now claims the lease for `PROOF_TOTAL_TIMEOUT_MS + 60000` like the tool lane so a long pass cannot outlive its own guard. Trust boundary: the sidecar is lease-protected runtime state whose only writer is `goal_evidence`, and the calling agent already holds shell access, so executing the recorded command adds no capability; cwd pinning and timeouts bound the blast radius. Consequence: `goal_complete` now runs the project's own tests and can take minutes, and a fabricated exit code can no longer close a goal. Rollback: revert `src/proof.ts`, drop the `runTests` option and its default, and keep declare-only verification with the sidecar unchanged.

## ADR-012 2026-10-24 Setting a goal resets its evidence sidecar

Context: the slash set lane seeded a fresh empty sidecar on every `/goal <objective>`, but the tool lane's `toolSet` only saved state. `goal_evidence` appends to whatever the file already holds, and the completion gate validates plus executes every criterion in it, so criteria recorded for finished goals accumulated in one session sidecar and gated later goals. Reproduced live: a session held six criteria from three goals, one recorded `pytest tests/ -q` that had since started failing, and every `goal_complete` returned `Complete blocked: evidence-invalid` after re-running the historical commands, with no way to see which criterion failed; duplicate-id rejection also made the bad entry impossible to correct in place. Decision: `toolSet` calls `saveEvidence(projectDir, emptyEvidence(clock.nowMs()), storage)` immediately after `saveGoalState`, mirroring `src/index.ts`, as a best-effort write so a failed seed never undoes a saved goal and the gate still fails closed on missing proof. Evidence keeps its existing per-session path, shape validation, sole-writer rule, and observed proof semantics; nothing in `verifier.ts` or `evidence.ts` changes. Consequence: a criterion can never outlive the goal it was recorded for, both set lanes behave identically, and a caller that wants to keep its proof keeps it by not re-setting. Known limitation left open: `goal_evidence` still rejects a reused id, so correcting a wrong criterion inside the same goal requires a new id. Rollback: delete the seed block in `toolSet`; state behavior and the slash lane are unaffected.

## ADR-014 2026-10-25 A blocked completion quotes its failures, and a proof command may carry its own env

Context: a real `goal_complete` blocked with `evidence-invalid. Add file citations plus passing tests to evidence` while the citations were correct and the recorded `mvn` command had failed only because the host ran JDK 17 instead of 21. `verifyLocal` had produced `test-failed:<id>:exit=1`, `tryCompleteWithEvidence` had passed it in `failures`, and both lanes threw the array away and printed one canned sentence — the same blind spot ADR-012 recorded as a known limitation. A proof command could also only inherit `process.env`, so a project needing a specific toolchain had to smuggle it into the command string.

Decision: one shared helper `describeVerificationFailure(reason, failures)` in `src/verifier.ts` builds the blocked message for both the tool lane and the slash lane; it quotes up to five failures and appends `(+N more)`, and keeps the generic sentence only when the verifier produced none. `EvidenceTestProof` gains an optional flat `env` string map, validated as strings only (a number would be stringified by the shell and silently change the command) and merged into the child environment last, after the hygiene variables, per command rather than globally.

Consequence: a block now says which criterion failed and how, so the agent fixes the cause instead of guessing; a toolchain pin travels with the proof that needs it and cannot leak into another criterion. Rollback: restore the two canned strings and drop the `env` field, its validation and the merge.

## ADR-013 2026-10-24 A session's own evidence file ends the legacy fallback

Context: ADR-012 made both set lanes seed an empty scoped evidence sidecar. On a machine that still had the pre-isolation `.opencode/goal-evidence.json`, that seed was undone on the very next write: an empty criteria list fails shape validation (`evidence-empty`), `loadEvidence` mapped the seeded file to `null`, and the legacy fallback then returned the old bucket, so `recordEvidence` merged four criteria from finished goals into the new sidecar and `goal_complete` blocked with `evidence-invalid` after an 82s proof pass. The fallback itself is correct for a session that has not migrated yet; what was wrong is that it could not tell an absent file from an empty one. Decision: `loadEvidence` checks whether the scoped path exists on disk and, when it does, reads it and returns that result without consulting the legacy path, including the `null` result an empty or invalid file produces. A session with no scoped file keeps the one-time legacy read. Deleting the legacy file on set was rejected: it would reach into runtime state the plugin only ever mutates through its own writers, and it would drop another session's not-yet-migrated evidence. Consequence: the legacy bucket can never resurrect criteria a set discarded, both lanes get the fix from the shared reader, other sessions' legacy data is preserved, and a corrupt scoped sidecar now fails closed instead of borrowing legacy proof, which matches the state rule in ADR-010. Rollback: restore the previous `loadEvidence` body, which falls back whenever the scoped read returns null.
